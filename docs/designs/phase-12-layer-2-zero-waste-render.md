## Problem Statement

Currently, Amane's desktop shell redraws continuously or requests frame callbacks (`wl_surface::frame`) across event-loop iterations even when all surfaces (persistent status bar, notifications, summon-on-demand modals) are completely static or hidden. In [`crates/amane/src/wayland/redraw.rs`](file:///home/hypokoto/dev/projects/dotfield/crates/amane/src/wayland/redraw.rs), the event loop triggers `state.request_frames()` unconditionally.

This causes:
1. Continuous Vulkan command buffer submissions and GPU power wakeups (preventing modern GPUs from dropping to ASPM L1/D3 idle power states).
2. Unnecessary CPU overhead in Calloop and Wayland IPC socket traffic.
3. Unneeded composition passes in Niri for invisible/hidden modal surfaces.

## What Makes This Cool

True **0 FPS idle silence** combined with **144Hz butter-smooth organic motion**:
- When you are reading code or typing in a terminal, Amane's GPU wakeups are literally **zero**.
- The instant you press a keybind to summon the app launcher or terminal manager, Amane springs into a 120–180ms ease-out transition running locked to display Vsync.
- The microsecond the easing transition reaches rest ($t \ge T_{\text{duration}}$), frame requests are parked instantly back to 0 Hz without a single trailing frame.

## Constraints

1. **Pure Rust + Amane Ecosystem**: Zero external C toolkits (GTK, Qt) or electron/slint dependencies.
2. **Strict Invariant from GEMINI.md**: Maintain ultra-low memory footprint (~60 MB RAM) and zero unnecessary background daemons.
3. **Motion Design Contract**: Animations must be restrained (120–180ms ease curves), respecting the "hyper-disciplined visual silence" design token.
4. **Wayland Layer-Shell Semantics**: Modal surfaces must adhere to `zwlr_layer_shell_v1` protocols without breaking keyboard focus or output hotplug re-negotiation.

## Premises

1. **Idle Frame Parking**: Render at 0 FPS (zero Vulkan command submissions and zero frame requests) when the UI is static and all modals are hidden. Redraws only happen during active 120-180ms ease transitions.
2. **Discrete Dirty-Checking**: The status bar only redraws when an external service publishes a state change (clock tick, workspace event, battery delta), rather than on a render loop timer.
3. **Surface-Level Unmapping**: Closed modal overlays must not commit frames or attach buffers while hidden, completely releasing compositor and GPU staging resources.

- **Coolest Version**: Zero-VRAM Framebuffer Freezing via Vulkan Timeline Semaphores & Shared Memory Snapshots. Evict heavy compute pass descriptors when parked, and pre-bake transition bezier deltas so summon transitions require zero re-calculation.

- **Existing Tools**: SCTK (`smithay-client-toolkit`) and Calloop provide 50% (Wayland frame callbacks & event loop). The missing 50% is the event-driven frame pacer, surface lifecycle state machine, and atomic dirty bit bus.
- **Suggested Build Order**: Replace unconditional `request_frames()` in `redraw.rs` with a dirty flag, build `AnimationPacer`, and verify 0.0% idle GPU utilization using hardware telemetry tools.

## Approaches Considered

### Approach A: Minimal Viable — Event-Gated Dirty Flag Parking
- **Summary**: Replace unconditional `request_frames()` in `redraw.rs` with an atomic `needs_redraw` flag set only by IPC/service updates.
- **Effort**: S (Small)
- **Risk**: Low
- **Pros**: Minimal diff; immediately drops idle polling.
- **Cons**: Animation loops must manually juggle dirty flags; hidden modals still hold compositor buffers.
- **Reuses**: Existing SCTK and Calloop handlers.

### Approach B: Ideal Architecture — State-Machine Render Coordinator & Animation Pacer (Approved)
- **Summary**: Introduce a `RenderCoordinator` with explicit surface states (`Parked(0Hz)`, `DirtySingleShot(1 frame)`, `Animating(Vsync-locked ease curve)`). Modal overlays are unmapped while closed. Summon transitions drive Vsync frames and immediately park at rest.
- **Effort**: M (Medium)
- **Risk**: Low-to-Medium
- **Pros**: Clean architectural separation; guaranteed 0% idle GPU wakeups; silky smooth 120-180ms motion; zero compositor memory overhead for hidden modals.
- **Cons**: Requires explicit animation interpolation bookkeeping.
- **Reuses**: SCTK layer-shell primitives, Calloop timer sources, and Vello compute rasterizer.

### Approach C: Lateral / Silicon-Level — Vulkan Pipeline Freezing & ASPM Deep Sleep
- **Summary**: Extends Approach B by tearing down Vulkan compute pipelines after 500ms of inactivity to force the GPU into PCIe ASPM L1/D3 power states.
- **Effort**: L (Large)
- **Risk**: High (potential 5-15ms wakeup hitch on first modal summon).
- **Pros**: Maximum possible battery savings on laptops.
- **Cons**: High complexity; driver-dependent latency tradeoffs.
- **Reuses**: Raw Wgpu/Vulkan device handles.

## Recommended Approach

**Approach B (State-Machine Render Coordinator & Animation Pacer)**:
Approved because it eliminates idle GPU power drain completely without introducing wakeup hitches or sacrificing the fluid 120–180ms motion design.

### Components to Implement:
1. **`SurfaceState` Machine**:
   - `Unmapped`: Modal is closed. No buffers attached, no frame callbacks registered.
   - `Parked`: Surface is mapped and visible (e.g. status bar), but static. No frame callbacks active.
   - `Dirty`: A service event (e.g., clock tick) marked the surface dirty. Redraw exactly once, commit damage buffer, return to `Parked`.
   - `Animating`: Active easing curve ($0 \le t < T$). Request `wl_surface.frame` on each Vsync tick, step interpolation, and transition to `Parked` when $t \ge T$.

2. **Animation Pacer**:
   - Monotonic clock-driven easing interpolator (`ease_out_cubic` / `ease_out_quad`).
   - Hooks into Wayland `frame` callback. When the last frame is reached, the callback is NOT re-requested.

3. **Dirty Event Propagation**:
   - Telemetry services (Niri IPC, battery, clock) send discrete notification signals rather than triggering continuous redraw loops.

### Section 1: Architecture Review

#### System & Component Boundaries
- **`SurfaceState` Machine** ([`crates/amane/src/wayland/redraw.rs`](file:///home/hypokoto/dev/projects/dotfield/crates/amane/src/wayland/redraw.rs)):
  - `Unmapped`: Modal is hidden; no buffers attached, zero compositor resources allocated.
  - `Parked`: Surface is visible (status bar), but static. Exactly 0 `wl_surface.frame` callbacks requested.
  - `DirtySingleShot`: A discrete service published a change (e.g. clock tick, battery delta). Re-render exactly once, commit damage, return to `Parked`.
  - `Animating`: Active easing transition ($0 \le t < T_{\text{duration}}$). Requests `wl_surface.frame` on each Vsync tick, advancing monotonic interpolation until $t \ge T$.

#### Design-Twice Architecture Evaluation
- **Shape 1 (Centralized RenderCoordinator in WaylandState)**: Centralizes all dirty flags, easing states, and window frame requests into a global manager.
  - *Risk*: High coupling between generic window management and shell-specific modal animations; requires passing window IDs back and forth across event loops.
- **Shape 2 (Decentralized Per-Window SurfacePacer with Shared Dirty Bitmask)**: Each window owns its `SurfaceState` and evaluates its redraw obligations locally when woken by Calloop or SCTK events.
  - *Decision*: **Shape 2 Selected**. Aligns with SCTK's window lifecycle model and GEMINI.md's modular zero-bloat invariant.

#### Red Flag Screen
- **Shallow Module**: Avoided. `SurfaceState` encapsulates transition states cleanly without leaking animation math to Calloop handlers.
- **Information Leakage**: The UI view renderers only draw scene graphs; they have zero knowledge of Wayland frame callback mechanics.
- **Temporal Decomposition**: Event dispatch is strictly reactive (socket ping or service event), eliminating timer tick loops.
- **Premature Generalization**: Focused exclusively on Wayland layer-shell surfaces under Niri.

### Section 4: Performance & Failure Modes Review

#### Steady-State vs Dynamic Performance Targets
- **Steady-State Desktop Idle**: Exactly **0 FPS**, 0 frame callbacks, 0 GPU command buffer submissions. GPU reaches ASPM L1/D3 idle power.
- **Modal Summon Latency**: Sub-millisecond opcode decode + immediate Wayland surface map on first Vsync frame.
- **Animation Motion**: Locked 144Hz/120Hz Vsync easing with monotonic wall-clock interpolation.

#### Edge Cases & Mitigations
1. **Multi-Output Hotplug**: When displays are added or removed, layer-shell surfaces receive configure events. Surfaces transition to `DirtySingleShot` to re-layout, then immediately park.
2. **Compositor Frame Starvation**: Under heavy GPU load (e.g. 3D gaming), frame callbacks may experience jitter. Monotonic timestamp progression ($t = (now - start) / duration$) guarantees animations complete in real time rather than running in slow motion.
3. **DPMS Monitor Sleep**: When monitors sleep, compositor halts frame callbacks. Shell stays in `Parked` state without accumulating unfulfilled frame requests.
