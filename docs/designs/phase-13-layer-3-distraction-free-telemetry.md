## Problem Statement
Standard Wayland desktop status bars (Waybar, Eww, Polybar) continuously poll hardware counters and display jittering CPU%, RAM%, and battery metrics, alongside flashing crimson notification badges. In a high-performance Wayland environment (Niri + Amane), this causes constant cognitive interruption, breaks deep focus flow, and wastes CPU/power on polling loops. The goal of Layer 3 is to transform Amane's status bar from a constant dashboard into an **exception-only HUD** that remains completely silent and visually dormant during normal operations, only surfacing actionable information when thresholds trip.

## What Makes This Cool
A completely naked, visually silent top bar during uninterrupted coding flow. When a heavy task spikes (such as `cargo build --release` or local model inference) or memory pressure stalls the kernel, an organic glowing amber/crimson capsule smoothly materializes via a 150ms cubic ease-out curve, displaying the exact offending process name (`[ 󰍛 rustc · 94% · 180ms stall ]`). The moment the compilation finishes or pressure drops, the HUD dissolves into total visual silence, instantly returning Wayland rendering to 0 Hz parking. When focusing on a full-width code column (1.0 width in `01 DEV`), the bar slides completely off-screen, reclaiming 100% of the display for pure code. If an anomaly trips while auto-hidden, the anomaly capsule slides down as a floating non-intrusive overlay with `exclusive_zone = 0` (zero window displacement) and dissolves when resolved.

## Constraints
- **Pure Rust & Zero-Bloat Invariant**: No external runtime daemons (`sysinfo` crate scanning all PIDs, Python shims, or shell subprocess forks). All logic lives inside `amane` and `amane-shell`.
- **Zero-Allocation Procfs Path**: Reading `/proc/stat`, `/proc/meminfo`, and `/sys/class/power_supply/BAT*/capacity` must use preallocated stack buffers (`[u8; 4096]`) and `pread()` on cached open file descriptors.
- **Wayland 0 Hz Frame Parking**: When no alerts are active, the telemetry subsystem must never request Wayland frames or wake up the GPU.
- **Polling Operational Model**: Under kernel PSI support, PSI triggers on `/proc/pressure/{cpu,memory}` handle stall alerts via `POLLPRI` at true 0.000% CPU and zero timer ticks. A relaxed 5-second `pread()` ticker monitors compute-only load (when no kernel stalls are triggered) and battery status; when operating on AC power with no alerts, the poller parks and relies on PSI interrupts.
- **Wayland Protocol Conformance**: Top bar auto-hiding must cleanly adjust `zwlr_layer_surface_v1` exclusive zone or unmap without crashing the Niri layout engine.
- **Controlled Chaos & Blacksite Visual Discipline**: Aesthetic alignment with Blacksite tokens (`#0A0A0E` obsidian background, `#20222E` borders, `#FFB000` warning accent, `#E63946` critical danger, `#8E8E9F` muted steel focus dot).

## Premises
1. **Exception-Gated HUD**: Suppress CPU/RAM/Battery meters during normal operation; only render accent/danger pills when thresholds trip (CPU > 85%, RAM > 80%, Battery < 20%), maintaining 0 Hz Wayland parking when idle.
2. **Zero-Allocation Procfs**: Metric polling must use cached open FDs for `/proc/stat`, `/proc/meminfo`, and `/proc/pressure` with `pread()` on stack buffers at 3–5s intervals, eliminating file descriptor thrashing and heap churn.
3. **Contextual Focus Shield**: In `01 DEV` and `04 SECURITY`, suppress non-critical notification animations (show static steel dot) and collapse/unmap the top bar when a full-width 1.0 column is focused.

## Approaches Considered

### Approach A: Pure Kernel PSI Sentinel & Anomaly Capsule
- **Summary**: Strictly event-driven architecture using Linux PSI triggers on `/proc/pressure/{cpu,memory}` registered with Calloop `POLLPRI`. Wakes up only on hardware stall interrupts.
- **Effort**: M (2–3 days)
- **Pros**: True 0.000% CPU overhead; zero polling timers; immediate reaction to memory pressure/thrashing before system freezes.
- **Cons**: Requires Linux 4.20+ with PSI enabled; doesn't cover simple high-CPU compute tasks that don't trigger pressure stalls.
- **Risk**: Low.

### Approach B: Fast pread() Procfs Poller & Threshold Pills
- **Summary**: Maintain persistent open FDs for `/proc/stat` and `/proc/meminfo`. Sample every 3–5s using `pread()` into a 4KB stack buffer without allocations. Top bar hides metrics unless CPU > 85% for 5s, RAM > 80%, or Battery < 20%.
- **Effort**: S (1 day)
- **Pros**: Universally supported on all Linux kernels; trivial state machine.
- **Cons**: Incurs periodic timer wakeups every 3–5s; lacks process attribution.
- **Risk**: Very Low.

### Approach C: Hybrid PSI Sentinel with pread() Fallback & Focus Shield (Selected)
- **Summary**: Combines event-driven PSI triggers with a lightweight, zero-allocation 5s `pread()` fallback for compute-only spikes. Wires culprit process attribution, workspace-aware DND notification suppression, and 1.0 column auto-hide into a cohesive distraction-free environment.
- **Effort**: M-L (3 days)
- **Pros**: Best-of-both-worlds: zero-poll kernel interrupts for system stalls, graceful fallback for compute spikes, actionable process attribution, and full workspace focus choreography.
- **Cons**: Coordinates multiple signals across Niri IPC, D-Bus notifications, and procfs.
- **Risk**: Low-Med.

## Recommended Approach
**Approach C (Hybrid PSI Sentinel with pread() Fallback & Focus Shield)**.
Rationale:
1. Gives the user the exact "whoa" factor: zero-poll stillness until a build or stall strikes, at which point the HUD shows the culprit process (`rustc`, `node`, `qemu`).
2. Provides a robust safety net: if running on a kernel without PSI enabled or a non-standard container, the zero-allocation `pread()` poller takes over seamlessly.
3. Unifies the visual workspace: the focus shield silences distracting peripheral notification animations and reclaims 100% of screen real estate on full-width code columns.

## Architecture & Technical Specification

### 1. Zero-Poll PSI Trigger & Procfs Engine (`crates/amane-shell/src/services/telemetry.rs`)
- **PSI Registration**:
  - Open `/proc/pressure/memory` and `/proc/pressure/cpu`.
  - Write trigger strings:
    - Memory: `some 100_000 1_000_000` (100ms stall in 1s window).
    - CPU: `some 200_000 1_000_000` (200ms stall in 1s window).
  - Register raw FDs into Calloop via `calloop::generic::Generic::new(fd, Interest::PRIORITY, Mode::Level)`.
- **Battery Telemetry Integration**:
  - Open `/sys/class/power_supply/BAT0/capacity` and `/sys/class/power_supply/BAT0/status` (or dynamically discovered battery node) once at initialization.
  - Read via `libc::pread(fd, buf.as_mut_ptr(), 64, 0)` during the 5s relaxed timer tick or upon AC/Battery status changes.
  - If capacity < 20% and status is "Discharging", trigger Warning; if capacity < 10%, trigger Critical.
- **Zero-Allocation Fallback (`pread` on Stack Buffer)**:
  - Keep open FDs for `/proc/stat` and `/proc/meminfo`.
  - Use `libc::pread(fd, buf.as_mut_ptr(), 4096, 0)` with zero heap allocations.
  - Parse `MemTotal`, `MemAvailable`, and `cpu` ticks directly via byte slice scanning.
- **Two-Point Delta Culprit Attribution Engine**:
  - Because `/proc/[pid]/stat` reports cumulative ticks (`utime + stime`), an instantaneous single pass cannot identify active CPU percentage.
  - When a CPU alert or PSI trigger trips, the attribution engine takes an initial snapshot of active PIDs and cumulative ticks into a fixed-size ring buffer (top 32 PIDs by RSS/ticks). The 250ms delta sampling window is scheduled via a non-blocking `calloop::timer::Timer` callback or dispatched on a background worker thread (ensuring the main Wayland event loop never blocks), after which a second snapshot is recorded.
  - Delta CPU % is calculated as:
    $$\Delta	ext{CPU}\% = rac{(	ext{utime}_2 + 	ext{stime}_2) - (	ext{utime}_1 + 	ext{stime}_1)}{\Delta	ext{TotalTime}} 	imes 100$$
  - The process with the highest positive delta is designated the active CPU culprit.
  - For memory pressure alerts, RSS is read directly from `/proc/[pid]/statm` (second field), requiring only a single pass over high-memory processes.
  - Results (PID, process comm name, and delta percentage) are cached for 2 seconds to eliminate redundant disk sweeps during sustained pressure.

### 2. Exception-Only Status Bar Capsule (`crates/amane-shell/src/ui/bar.rs`)
- **State Machine & Asymmetric Hysteresis**:
  - `Dormant` (normal load): Metrics hidden. Telemetry width in bar = 0. 0 Hz Wayland frame parking.
  - `Trip Conditions`:
    - CPU Warning: CPU > 85% for 5s (amber `#FFB000`).
    - CPU Critical: CPU > 95% or PSI CPU trigger active (danger `#E63946`).
    - RAM Warning: RAM > 80% (amber `#FFB000`).
    - RAM Critical: RAM > 90% or PSI Memory trigger active (danger `#E63946`).
    - Battery Warning: Battery < 20% & Discharging (amber `#FFB000`).
    - Battery Critical: Battery < 10% & Discharging (danger `#E63946`).
  - `Asymmetric Recovery Conditions` (prevents flapping at boundary):
    - CPU clears only when dropping below 75% for 3 seconds.
    - RAM clears only when dropping below 72%.
    - Battery clears only when above 25% or status transitions to "Charging".
  - `Minimum Display Floor`: 3 seconds minimum display duration once triggered.
  - `Dismissal`: Once load drops below recovery thresholds and display floor expires, fade out over 150ms and return Wayland event loop to 0 Hz.
- **Pointer Interactivity & Process Termination**:
  - The top bar layer surface uses `zwlr_layer_surface_v1::KeyboardInteractivity::None` to prevent stealing keyboard or focus from client terminal/editor windows.
  - Pointer events (`WlPointer::button`) over the anomaly pill are captured in `amane::wayland::pointer`.
  - Left-clicking the kill icon (`󰅖 Kill`) calls `libc::kill(pid, libc::SIGTERM)`. If held or re-clicked within 1 second, it escalates to `libc::SIGKILL`.

### 3. Context-Aware Focus & Notification Shield (`crates/amane-shell/src/services/niri.rs` & `notifications.rs`)
- **Workspace DND Policy**:
  - Query current workspace from `NiriService`.
  - When active workspace is `01 DEV` or `04 SECURITY`:
    - Suppress all animated popups and sound cues.
    - Status bar notification pill renders as a quiet, static steel dot (`#8E8E9F`).
    - Only `Urgency::Critical` (D-Bus byte `2`) bypasses the shield with an audible alert and amber frame.
  - On other workspaces (`02 WEB`, `03 CHAT`), normal notification popups proceed.

### 4. Full-Width Column Auto-Hide & Overlay Capsule (`crates/amane-shell/src/ui/bar.rs` & `crates/amane-shell/src/services/niri.rs`)
- **Column Geometry Listener**:
  - Monitor focused window column width from Niri IPC event stream (`FocusedWindowChanged` / `WindowLayoutChanged`) in `crates/amane-shell/src/services/niri.rs`.
  - When focused column width in `01 DEV` equals `1.0` (full width):
    - Slide the top bar off-screen (translate Y by `-36px` over 150ms).
    - Set `exclusive_zone` to `0` so the editor window takes 100% vertical pixels without a gap.
  - When column width narrows or focus shifts to multi-column, slide the bar back down and restore `exclusive_zone = 32`.
- **Anomaly Priority in Full-Width Mode**:
  - If a Critical or Warning anomaly trips while the bar is auto-hidden in full-width mode, the bar does *not* push the client window down.
  - Instead, the anomaly capsule slides down as an independent floating overlay with `exclusive_zone = 0` (layer `Overlay`), staying anchored at the top-right display margin.
  - When the anomaly clears, the floating capsule slides back up, preserving uninterrupted code layout throughout the incident.
