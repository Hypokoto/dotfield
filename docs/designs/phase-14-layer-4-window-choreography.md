## Problem Statement
In modern tiling desktop environments, window management and project context remain fragmented. In Dotfield:
1. `terminal_manager.rs` merely switches between four installed terminal emulator binaries (Foot, Kitty, Alacritty, Ghostty), encouraging tool fragmentation without solving project workflow switching.
2. In Niri's infinite horizontal ribbon, windows open arbitrarily without deterministic column widths or workspace routing.
3. Companion developer tooling (such as `cargo watch`, test runners, compiler output, or local AI/LLM logs) steals keyboard focus, jarring deep code editing flow.
4. Quick scratchpad notes or ephemeral commands either scroll the horizontal ribbon or require awkward manual window positioning.

## What Makes This Cool
**"The Living Worktree Cell & Spatial Ribbon Warping"**
- **Atomic Worktree Cells**: Every project is represented on Niri's horizontal ribbon as an atomic pair: a primary Neovim/IDE column pinned at `2/3` width and an elastic companion sidecar (`app-id = "sidecar-..."`) at `1/3` width with `open-focused false`.
- **Project Topology Router**: `amane terminals` is repurposed into an instantaneous developer session switcher. It scans active Tmux sessions, Git worktrees, and project roots in `~/dev/projects/`. When selected, if an emulator matching `app-id = "dev.<project>"` is open, Niri smoothly warps the ribbon directly to that column. If unmaterialized, it launches the atomic pair on workspace `01 DEV`.
- **Hybrid Scratchpad System**: Instant centered 960x600 floating scratchpad (`floating-term`) summoned on `Mod+Ctrl+Return` over the active workspace without horizontal scroll churn, alongside elastic 1/3 companion sidecars for long-lived logs. Screen lock remains strictly preserved on `Mod+Escape`.
- **Fast-Path IPC Opcode `0x02` (`OP_TERMINAL_MGR`)**: Reuses the dedicated opcode `0x02` (alias `topology`, `terminals`, `terminal-manager`) over Unix stream sockets for sub-millisecond modal invocation (~1.2ms), maintaining 0 Hz frame callback parking at rest and zero conflicts with system tray (`OP_TRAY = 0x08`).

## Constraints
- **Sub-Millisecond Summon**: Modal summon must not exceed 2ms latency from keybind press to Wayland frame render; direct opcode `0x02` over Unix stream socket (`amane.sock`).
- **Pure Rust + Niri Native IPC**: Window queries and focus shifts must use persistent Niri socket connection (`Request::Windows`, `Action::FocusWindow`), never spawning `niri msg` CLI subcommands.
- **Zero-Poll In-Memory Topology Cache with Async Refresh**: Project roots and Git worktree lists are cached in memory; modal summoning reads exclusively from memory without blocking the UI thread on disk I/O; cache refresh occurs asynchronously on background worker threads or on directory change triggers.
- **Controlled Chaos Token Compliance**: All UI borders, badges, and card states must use canonical Dotfield tokens (`border_focus`, `accent`, `steel`, `void_black`, `radius::CARD`).

## Premises
1. **Topology over Emulators**: Developers work in projects, repositories, and sessions—not arbitrary terminal emulator brands. Standardizing on Kitty/Foot and routing sessions provides vastly superior cognitive flow.
2. **Deterministic Ribbon Routing**: Secondary compiler output and companion sidecars must never steal focus (`open-focused false`) or push code offscreen.
3. **Spatial Navigation over Floating Hacks**: Tiling window managers are fastest when project context is a stable spatial ribbon coordinate that can be warped to via compositor IPC.

## Approaches Considered

### Approach A: Standalone Daemon & Terminal TUI (`sesh` + `fuzzel`)
- External shell scripts and Fuzzel/Sesh launchers called via keybinds.
- *Rejected*: Incurs process-forking overhead (~25-40ms), violates Dotfield's zero-bloat/zero-external-daemon principle, and cannot coordinate Niri window IDs with Wayland layer-shell modals.

### Approach B: Workspace-per-Project Virtual Desktop Allocator
- Create a dedicated dynamic Niri workspace for every Git worktree or project.
- *Rejected*: Fragmentation of the canonical 5-workspace model (`01 DEV`, `02 SYSTEM`, `03 RESEARCH`, `04 SECURITY`, `05 SCRATCH`), breaking muscle-memory hotkeys (`Mod+1` through `Mod+5`).

### Approach C: Integrated Amane Topology Router & Living Worktree Cells (Recommended)
- Repurpose `crates/amane-shell/src/ui/terminal_manager.rs` into the Topology Switcher summoned via opcode `0x02`.
- In-memory `TopologyService` in `crates/amane-shell/src/services/topology.rs` caching `~/dev/projects/`, Git worktrees, and active Tmux sessions, with async background refresh.
- Smart Spatial Warp via `NiriService::focus_window(id)`.
- Companion sidecar launcher CLI (`amane-msg sidecar`) inspecting the currently focused window's project context to spawn the matched sidecar.
- Declarative Niri window rules in `compositor/niri/conf.d/06-window-tiling.kdl` and `07-floating.kdl`:
  - `^dev\\.` windows: `default-column-width { proportion 0.66667; }`
  - `^sidecar-` windows: `default-column-width { proportion 0.33333; }` and `open-focused false`
  - `floating-term`: `open-floating true`, `960x600` fixed geometry.

## Recommended Approach
Implement **Approach C**:
1. **Core Topology Engine**:
   Create `crates/amane-shell/src/services/topology.rs` exposing `TopologyService`, discovering:
   - Git worktrees: `git worktree list --porcelain` across project directories in `~/dev/projects/`.
   - Active Tmux sessions: `tmux list-sessions -F "#{session_name}\t#{session_path}"`.
   - Standard fallback projects in `~/dev/projects/`.
   - Maintain an in-memory `ArcSwap<Vec<ProjectTarget>>` cache. UI reads never block on I/O. Background worker thread refreshes cache periodically (or on modal summon trigger dispatched asynchronously).
2. **Niri Spatial Warp Engine**:
   In `crates/amane-shell/src/services/niri.rs`, implement `jump_or_spawn_project(target: &ProjectTarget)`:
   - Query cached `NiriWindowService` windows for matching `app_id == format!("dev.{}", target.slug)`.
   - If present, dispatch `Action::FocusWindow { id }` to pan the Niri ribbon smoothly.
   - If unmaterialized:
     - First ensure workspace `01 DEV` is active: dispatch `Action::FocusWorkspace { reference: WorkspaceReferenceArg::Name("01 DEV".into()) }`.
     - Spawn primary terminal: `Command::new("kitty").args(["--app-id", &format!("dev.{}", target.slug), "-d", &target.path.to_string_lossy(), "-e", "tmux", "new-session", "-A", "-s", &target.slug]).spawn()`.
     - Automatically spawn linked sidecar companion column: `Command::new("kitty").args(["--app-id", &format!("sidecar-{}", target.slug), "-d", &target.path.to_string_lossy()]).spawn()`.
3. **Amane Modal UI & Fast-Path IPC**:
   Update `ui/terminal_manager.rs` to render the interactive list of project targets with fuzzy search, git branch/worktree badges, and tmux session indicators.
   Reuse and wire opcode `0x02` (`OP_TERMINAL_MGR`) with aliases `"topology"` in `crates/amane/src/ipc.rs` and `crates/amane-shell/src/bin/amane-msg.rs`.
   Add `amane-msg sidecar` subcommand to inspect focused window title/app-id and spawn the matching companion sidecar.
4. **Compositor Declarative Rules & Disambiguated Binds**:
   Update `compositor/niri/conf.d/06-window-tiling.kdl`, `07-floating.kdl`, and `08-binds.kdl`:
   - `Mod+Return`: Launch default terminal in working directory.
   - `Mod+Shift+Return`: Summon Topology Switcher (`amane-msg topology`, opcode `0x02`).
   - `Mod+Alt+Return`: Spawn companion sidecar for currently focused project (`amane-msg sidecar`).
   - `Mod+Ctrl+Return`: Summon centered 960x600 floating scratchpad (`kitty --app-id=floating-term`).
   - `Mod+Escape`: Preserved strictly for screen locking (`scripts/lock.sh`).
