## Problem Statement

Currently in Wayland desktop environments and Niri, connecting external displays (projectors, TVs, conference room displays) requires manual Kanshi reloading or blind display output management. This causes jarring window ribbon shifts, misaligned DPI scaling, and severe privacy hazards: sensitive personal notifications, private chat tabs, and security tooling (`04 SECURITY`) can inadvertently appear on a public conference projector. Furthermore, there is no native, low-latency mechanism to enter a stage-ready "Presentation Mode" that guarantees zero notifications, locks external displays to dedicated public workspaces, and surfaces an elapsed presentation timer HUD for the speaker.

## What Makes This Cool

The **Zero-Disruption Presentation Shield**: Connecting an external HDMI or DisplayPort projector automatically or via a 1-byte fast-path IPC opcode (`amane-msg presentation`) engages an atomic privacy and stage-armor state.
- External outputs are strictly isolated to a designated public workspace (`05 PRESENTATION` or `03 RESEARCH`).
- All personal notifications, OSD overlays, and audio alerts are muted or buffered without dropping events.
- An elapsed-time presentation stopwatch HUD pill (`󰐩 [PRESENTING] 14:32`) materializes *exclusively* on the internal primary laptop bar, keeping the speaker oriented and on schedule without revealing notes or telemetry to the audience.

## Constraints

1. **Zero-Poll Wayland Rendering (0 Hz idle)**: Display hotplug tracking and presentation mode must remain completely event-driven. When the presentation timer ticks (1s interval) or an output hotplugs, only the dirty primary bar surface or reconfigured output is damaged; the shell must not spin the GPU.
2. **Deterministic Workspace Quarantine**: Niri's spatial ribbon must forbid private workspaces (`01 DEV`, `04 SECURITY`) from being focused on or migrated to external outputs during Presentation Mode.
3. **No Breaking Keybind Changes**: Keep `Mod+P` or `Mod+Shift+P` for presentation mode toggle without colliding with existing compositor keybindings.
4. **No New Heavy Daemons**: Leverage existing `kanshi` for output management modes; do not introduce heavy GTK display configurators or background node/python daemons.
5. **Fast-Path IPC Opcode**: Use opcode `0x0E` (`OP_PRESENTATION`) in `amane` and `amane-msg` for sub-2ms toggle latency.

## Premises

1. **Zero-Disruption Presentation Mode**: A 1-byte opcode toggle (`amane-msg presentation`, opcode `0x0E`) that atomically engages an in-daemon presentation shield: silences notifications, pins external displays to public workspaces, and activates an elapsed presentation timer in the status bar.
2. **Kanshi Hotplug Bridge**: Output connection and disconnection events automatically adjust Kanshi profiles and signal Amane's `DisplayService` without tearing or desktop freezing.
3. **Asymmetric Primary/Secondary Output Isolation**: Primary laptop display (`eDP-1`) retains full system telemetry, workspace navigation, and speaker stopwatch; secondary external display receives a pristine, distraction-free viewport.

## Approaches Considered

### Approach A: Standalone Bash Script (`scripts/presentation-toggle.sh`)
- Rely on an external shell script that runs `makoctl mode -a do-not-disturb`, calls `niri msg action focus-workspace 05-presentation`, and updates a temporary state file in `/tmp`.
- *Ruled out*: Introduces shell process spawn overhead (~25-40ms), race conditions across state files, and cannot render an integrated, GPU-accelerated presentation timer HUD inside Amane's native Vello bar.

### Approach B: Kanshi-Only Display Profiling
- Define Kanshi profiles for dual-monitor setups and execute shell commands inside `kanshi/config`.
- *Ruled out*: Kanshi alone is unaware of Amane's internal UI state, notification inhibition, and Niri window ribbons. It manages physical output modes, not application workspaces or privacy shields.

### Approach C (Recommended): Native `PresentationService` + IPC Opcode `0x0E` + Kanshi Hotplug Hook
- Implement native `PresentationService` in `crates/amane-shell/src/services/presentation.rs` managing `PresentationState` (`active: bool`, `start_time: Option<Instant>`).
- Wire opcode `0x0E` (`OP_PRESENTATION`) in `crates/amane/src/ipc.rs` and `amane-msg presentation`.
- **Notification Suppression & Draining**: In `NotificationService` and `amane-shell`, check `PresentationService::is_active()`. Non-critical notifications are captured into an in-memory FIFO ring buffer (capped at 50 items) and muted from screen rendering. Critical urgency alerts (e.g., Battery < 5% imminent shutdown) bypass the shield and display a discreet notification exclusively on `eDP-1`. Disengaging presentation mode drains and displays the buffered items sequentially.
- **Single-Head & Multi-Head Adaptability**: If invoked with no external display connected, Presentation Mode cleanly activates locally (starting the primary timer HUD and silencing notifications without failing or dispatching invalid output migrations), providing a distraction-free rehearsing and local screen-recording environment.
- In `bar.rs`, render an animated presentation pill `󰐩 [PRESENTING] 14:32` strictly on internal display `eDP-1`.
- In `NiriService`, enforce workspace routing to `05 PRESENTATION` on external outputs when detected.
- In `kanshi/config`, invoke `amane-msg presentation` on projector profile activation.

## Open Questions

1. Should disconnecting the external cable automatically disengage Presentation Mode, or should it persist until explicitly toggled off by the user?
   - *Decision*: Auto-disengage on external output disconnect, but allow manual toggle anytime via `Mod+Shift+P` / `amane-msg presentation`.
2. Which workspace should be designated as the presentation workspace?
   - *Decision*: Dedicated `05 PRESENTATION` workspace, created dynamically or mapped to existing `03 RESEARCH` if `05` is unconfigured.
3. How are suppressed notifications handled upon presentation exit?
   - *Decision*: Drained from an in-memory FIFO buffer (max 50) and rendered sequentially with 3-second toasts. Critical battery alerts bypass suppression during presentation.

## Success Criteria

1. `amane-msg presentation` dispatches via opcode `0x0E` in < 2ms without spawning shell subprocesses.
2. When Presentation Mode is active:
   - Notifications are silenced (buffered silently, no layer-shell banners appear).
   - An elapsed-time timer pill (`󰐩 [PRESENTING] MM:SS`) renders on the primary internal bar.
   - The secondary/external display is quarantined from displaying `04 SECURITY` or `01 DEV`.
3. Toggling off presentation mode flushes buffered notifications gracefully and unmaps the timer pill.
4. Kanshi profiles in `kanshi/config` successfully trigger presentation hooks on external display connection.
5. All automated unit tests, clippy checks, formatting, and pre-commit hooks pass with zero warnings.
