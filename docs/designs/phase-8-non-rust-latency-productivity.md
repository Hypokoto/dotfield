## Problem Statement
Dotfield's core Rust compiler, transactional deployment engine, and Slint GUI utilities are complete, type-safe, and robust. However, the developer experience and perceived performance of a Linux desktop environment are fundamentally bounded by its non-Rust layer: Wayland compositor frame scheduling, typematic input repeat rates, terminal PTY rendering pipelines, shell completion dump latency, multiplexer escape handling, launcher search responsiveness, and background script overhead. Without holistic synchronization across these non-Rust components:
- Sway and Niri wait on default frame queues or sluggish key repeat delays (250ms delay, 35 rate), introducing perceptible input lag.
- Zsh shell initialization takes 50–150ms on every new terminal split due to un-cached `compinit` security audits, and vi-mode suffers a 150ms lag on `<Esc>`.
- Tmux introduces an unconfigured 500ms escape wait (`escape-time`), causing stutter in Neovim mode switching.
- Terminals (Kitty, Foot) run standard frame buffers without low-latency repaint or font glyph acceleration.
- Screenshot captures perform synchronous disk writes before copying to clipboard, stalling user interaction.

Phase 8 eliminates these bottlenecks across the entire non-Rust desktop substrate while preserving the Controlled Chaos visual identity and security profiles.

## What Makes This Cool
"The Zero-Lag Cockpit" — Achieving instantaneous end-to-end responsiveness without altering a single line of Rust code. Pressing `<Esc>` in Neovim inside Tmux switches modes in 0ms; terminal tabs spawn in <10ms; typing in Sway/Niri feels tethered directly to the display refresh via VBLANK-synchronized rendering (`max_render_time 1`); and screenshots stream directly into the clipboard pipeline while writing asynchronously.

## Constraints
1. **Scope Restriction**: Modify ONLY non-Rust configuration fragments, scripts, themes, and documentation. No Rust crate modifications unless a generated template fragment in `crates/dotfield-core/src/compiler.rs` strictly requires matching output.
2. **Controlled Chaos Palette Fidelity**: All modified configuration files must strictly maintain the `#0A0A0C` (Void), `#121216` (Obsidian), `#1C1C23` (Graphite), `#34343D` (Iron), `#FFB000` (Amber), `#E63946` (Crimson), and `#E8E6E3` (Bone) design tokens defined in [`PALETTE.md`](file:///home/hypokoto/dev/projects/dotfield/PALETTE.md).
3. **Security Invariants**: Sandboxing policies (Firejail, AppArmor, Flatpak, NFTables) must remain intact without relaxing isolation.
4. **Standalone Usability**: Base configs must remain fully usable as standalone Wayland desktop environments even without Dotfield profile compilations.
5. **Quality Gates**: All 10 pre-commit gates (`pre-commit run --all-files`) and 25 unit tests (`cargo test`) must pass cleanly.

## Premises
1. **End-to-End Latency Coherence**: Squeezing milliseconds out of shell prompt is futile if Tmux has a 500ms escape delay or Sway renders 2 frames ahead of vblank. All layers (compositor, terminal, multiplexer, shell, editor) must be synchronized.
2. **Zero Performance Regressions in Security**: Hardening rulesets (Firejail, AppArmor, NFTables) must maintain strict isolation without adding measurable process spawning or packet filtering overhead.
3. **Preserved Aesthetic Integrity**: Every optimization must respect the Controlled Chaos color palette ([`PALETTE.md`](file:///home/hypokoto/dev/projects/dotfield/PALETTE.md)) without visual breaking changes.
4. **Scope Discipline**: We optimize all non-Rust configuration fragments, scripts, themes, and documentation without modifying core Rust engine logic unless a template fragment generator specifically requires it.

## Approaches Considered
### Approach A: Comprehensive Low-Latency Stack Alignment (Chosen)
- **Summary**: Deep tuning pass across all 9 non-Rust subsystems: Sway frame timing (`max_render_time 1`) and typematic rate (`repeat_delay 200`, `repeat_rate 50`), Niri snappy animations, Zsh 24h `compinit -C` cache and `KEYTIMEOUT=1`, Starship `scan_timeout = 10` & `command_timeout = 150`, Tmux `escape-time 0` & vi-mode clipboard pipe, Kitty `repaint_delay 6` & `input_delay 1`, Foot fast font glyph rendering, Neovim 100ms `updatetime` & `undofile`, Fuzzel/Rofi fuzzy caching, and direct pipe Grim screenshotting.
- **Effort**: M
- **Risk**: Low
- **Pros**: Eliminates input lag across all tiers; zero Rust changes; preserves aesthetics and security.
- **Cons**: Modifies ~10 configuration files.
- **Reuses**: Leverages existing modular configs in `compositor/`, `shell/`, `terminals/`, `multiplexer/`, `nvim/`, `launcher/`, and `scripts/`.

### Approach B: Targeted Terminal & Shell Quick-Fix
- **Summary**: Focus solely on Zsh `KEYTIMEOUT=1`, Tmux `escape-time 0`, and Kitty delays.
- **Rejection Reason**: Leaves compositor frame scheduling, typematic repeat delays, launchers, screenshot pipelines, and Neovim unoptimized.

### Approach C: Aggressive Ultra-Minimal Performance Strip
- **Summary**: Disable all animations, turn off git status prompts, strip borders/gaps, minimize bar polling.
- **Rejection Reason**: Severely degrades developer ergonomics and destroys the Controlled Chaos aesthetic identity.

## Recommended Approach
Approach A: Comprehensive Low-Latency Stack Alignment. It addresses every link in the input-to-render chain, ensuring the workstation feels uniformly instantaneous.
