## Problem Statement
Dotfield provides a robust declarative ricing engine, transactional compilation pipeline, and low-latency system configurations (completed in Phases 1–8). However, the human interface surface—the visual craft, micro-interactions, layout rhythm, and component affordances across the desktop environment—requires a rigorous, out-of-distribution upgrade to fulfill the Controlled Chaos aesthetic philosophy defined in [`PALETTE.md`](file:///home/hypokoto/dev/projects/dotfield/PALETTE.md) and the craft standards of [`reference/craft-floor.md`](file:///home/hypokoto/.agents/skills/impeccable/reference/craft-floor.md).

Specifically:
1. **Native Slint GUIs (`crates/dotfield-gui/`)**:
   - `palette.slint`: Currently exports only a bare subset of colors. It lacks tokens for Pale Amber (`#FFD166`), Steel (`#8B949E`), Success Green (`#7BC47F`), Blood Red (`#9D0208`), as well as standardized typography scales, spacing metrics, and corner radii.
   - `hud.slint` (Keybind HUD): Lacks a dedicated zero-result empty state when a search query finds no matches; lacks visual distinction between modifier keys (`Super`, `Ctrl`, `Alt`) and action keys (`Return`, `Space`); lacks keyboard navigation hints (`[Esc]` to close, `[↑/↓]` to scroll); uses a raw Unicode `✕` close button; and lacks styled category badge pills.
   - `switcher.slint` (Profile Switcher): Profile cards feel static and lack depth; active vs. inactive elevation states are minimal; cards do not visually surface the quick-switch numeric hotkeys (`[1]`, `[2]`, `[3]`); metadata (compositor, apps, security) is displayed as concatenated plain text rather than discrete semantic badges; and the Apply button lacks micro-interaction states.
2. **Application Launchers (`launcher/fuzzel/` & `launcher/rofi/`)**:
   - Fuzzel and Rofi configurations lack refined border radii (8px), padding symmetry, prompt styling, and strict Controlled Chaos color fidelity.
3. **Desktop Notifications (`mako/config`)**:
   - Notification styling requires consistent 8px radii, distinct urgency borders (Amber for normal, Iron for low, Crimson for critical), and readable high-contrast typography.
4. **Status Bar & Prompt Presentation (`i3-rust/` & `shell/starship/`)**:
   - i3status-rust and Starship prompt configurations need refined glyph alignments, clean delimiter symbols, and mode-dependent visual accents (Amber for normal vi-mode, Bone for insert, Crimson for visual).

Phase 9 resolves these deficiencies across the entire desktop graphical stack, transforming Dotfield into an aesthetically peerless, tactile, and coherent Linux environment.

## What Makes This Cool
"Bespoke Desktop Luxury" — Elevating Dotfield from utilitarian config files into a museum-grade Linux desktop experience. Summoning the Keybind HUD (`Super+slash`) displays a crystal-clear, industrial HUD with styled keyboard modifier chips and instant reactive filtering; opening the Profile Switcher (`Super+p`) presents cards with tactile `[1]`, `[2]`, `[3]` hotkey chips, smooth hover elevations, and semantic security badges, making profile switching feel like operating a premium workstation cockpit.

## Constraints
1. **Controlled Chaos Palette Invariant**: All UI components, borders, backgrounds, text, and states must strictly derive from [`PALETTE.md`](file:///home/hypokoto/dev/projects/dotfield/PALETTE.md):
   - Void (`#0A0A0C`): Primary root backdrop.
   - Obsidian (`#121216`): Layer 1 surfaces (cards, panels, input fields).
   - Graphite (`#1C1C23`): Layer 2 interactive surfaces (selection, elevated cards).
   - Iron (`#34343D`): Structural dividers, inactive borders.
   - Bone (`#E8E6E3`): High-contrast primary text.
   - Ash (`#A1A1AA`): Secondary text, metadata.
   - Industrial Amber (`#FFB000`): Primary accent, active borders, keybind highlights.
   - Pale Amber (`#FFD166`): Hover highlights, focused borders.
   - Crimson (`#E63946`): Urgency, critical warnings, errors.
   - Steel (`#8B949E`): Neutral secondary controls and structural accents.
   - Success Green (`#7BC47F`): Successful operations.
2. **Impeccable Craft Floor**: Adhere strictly to [`reference/craft-floor.md`](file:///home/hypokoto/.agents/skills/impeccable/reference/craft-floor.md):
   - Contrast ratio >= 4.5:1 for body copy, >= 3:1 for large text.
   - No lazy nested containers, no gradient text, no monospace as a costume, no un-themed window controls.
   - Clear visual hierarchy, generous spacing rhythm, and purposeful state transitions (hover, focus, active, empty).
3. **Slint Build & Runtime Integrity**: All `.slint` files must compile cleanly with `slint-build` in `crates/dotfield-gui/build.rs` without warnings or type mismatches.
4. **Rust Quality & Zero-Warning Policy**: All Rust crates (`dotfield-core`, `dotfield-cli`, `dotfield-gui`, `dotfieldd`) must pass `cargo clippy --all-targets -- -D warnings` and `cargo test`.
5. **Pre-Commit Quality Gates**: All 10 pre-commit hooks (`pre-commit run --all-files`) must pass with 100% success.

## Premises
1. **Visual Hierarchy Directs Attention**: A dark industrial interface requires disciplined contrast. Void and Obsidian provide calm; Amber guides active intent; Crimson signals critical state; Bone ensures legible typography.
2. **Tactile Affordances Empower Muscle Memory**: Profile switchers and keybind HUDs are productivity tools; surfacing hotkeys (`[1]`, `[2]`, `[3]`, `[Esc]`, `[Return]`) directly on UI components reduces cognitive friction.
3. **Cohesive Design Tokens Prevent Visual Drift**: Centralizing typography, spacing, radii, and color tokens in `ui/palette.slint` guarantees visual consistency across all Slint windows.
4. **Desktop Aesthetic Harmony**: Launchers (Fuzzel, Rofi), notifications (Mako), status bars (i3status-rust), prompts (Starship), and compositors (Sway, Niri) must share identical border radii, padding rhythms, and token mappings.

## Approaches Considered
### Approach A: Comprehensive End-to-End Visual Craft & Token System (Chosen)
- **Summary**:
  1. Expand `crates/dotfield-gui/ui/palette.slint` with complete Controlled Chaos colors, typography scale, spacing tokens, and corner radii.
  2. Overhaul `crates/dotfield-gui/ui/hud.slint`: Add zero-match empty state, styled keyboard modifier chips (`Super`, `Return`), category badge pills, search bar focus ring, styled vector close button, and keyboard navigation hints.
  3. Overhaul `crates/dotfield-gui/ui/switcher.slint`: Add tactile `[1]`, `[2]`, `[3]` hotkey chips, interactive card hover elevations, discrete semantic metadata badges (Compositor, Apps, Security), tactile Apply button states, and rich generational status bar.
  4. Update `crates/dotfield-gui/src/main.rs`: Ensure model bindings, search filtering, and state feedback seamlessly integrate with the new Slint properties.
  5. Refine Launchers (`launcher/fuzzel/fuzzel.ini`, `launcher/rofi/config.rasi`): 8px border radii, symmetric padding, matching Controlled Chaos tokens.
  6. Refine Notifications (`mako/config`): 8px radius, distinct urgency border levels (Amber, Iron, Crimson), readable typography.
  7. Refine Status Bar & Prompts (`i3-rust/config.toml`, `shell/starship/starship.toml`): Clean glyph spacing, vi-mode visual indicator states.
- **Effort**: M
- **Risk**: Low
- **Pros**: Complete visual harmony across the entire Linux desktop environment; Slint GUIs become flagship showcase pieces; strictly satisfies `PALETTE.md` and `craft-floor.md`.
- **Cons**: Requires touching multiple component configs and Slint templates.
- **Reuses**: Leverages existing Slint modules and modular configuration files.

### Approach B: Slint GUI-Only Polish
- **Summary**: Refactor only `crates/dotfield-gui/ui/*.slint` files, leaving launchers, notifications, and status bar untouched.
- **Rejection Reason**: Leaves desktop launchers and notification banners looking disconnected and unharmonized with the new GUI styling, breaking overall desktop immersion.

### Approach C: Superficial Token Hex Patch
- **Summary**: Adjust hex values in existing files without redesigning empty states, hotkey badges, modifier chips, or card elevation.
- **Rejection Reason**: Fails to fix fundamental UX and accessibility issues; violates Impeccable craft principles.

## Recommended Approach
Approach A: Comprehensive End-to-End Visual Craft & Token System. It delivers cohesive visual beauty, crisp typography, and tactile ergonomics across both native Rust Slint GUIs and non-Rust Wayland desktop fragments.
